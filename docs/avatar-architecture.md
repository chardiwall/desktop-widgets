# Desktop avatar architecture

## Decision

Build a portable avatar core and use AzClock as its first desktop host. Add an avatar element and a clock-local overlay to AzClock, wiring both through a small host adapter. Develop against a pinned source checkout in a test environment, then maintain the change in a fork or upstream it. Keep the settings app independent. The installed host is AzClock 16.1 (`azclock@azclock.gitlab.com`) on GNOME Shell 50.1. Its image element handles still images and optional periodic remote refresh. The installed host also carries a desk-light input patch. Capture that patch and test locked-widget input and the light knob before deploying an avatar build. [Ubuntu decision](adr/0001-reuse-gnome-widgets-on-ubuntu.md) · [Research notes](avatar-research.md) · [AzClock listing](https://extensions.gnome.org/extension/5156/desktop-clock/) · [AzClock source](https://gitlab.com/AndrewZaech/azclock)

Use a small event-driven state machine with weighted, timed activity selection. A behaviour tree or physics simulation would add complexity to a character that performs one authored sequence at a time on a handful of known surfaces. Blender renders the transparent poses offline. The Shell element presents those poses and moves one actor, with a temporary actor for the text bubble or swing when needed.

```text
Desktop and OS capabilities <──> Host adapter <──> Portable avatar core
window, input, timing, storage    native rendering   activity and focus
notifications, power, locale     and scheduling      prayer reminders
                                       ↑
                                Clips and anchors
                                  Blender export
```

## Desktop host interface

Use plain JavaScript ES modules for the core so GNOME can import them directly. Keep the activity controller, focus rules, prayer reminder policy and clip metadata independent of GJS, Clutter, browsers and desktop paths. Put OS side effects in the adapter. Wire the first release in the AzClock process through ordinary function calls. The core has no daemon or IPC dependency. If a future native host needs a different runtime, prove it can run the same core before choosing an embedded runtime or an on-demand local process. Frame playback and texture ownership stay inside the host in either case.

| Direction | Interface |
| --- | --- |
| Host to core | Dispatch menu commands, scene geometry and capability changes, clip completion, deadline wakeups and lifecycle events. Supply wall-clock time for prayer and focus deadlines and a monotonic clock for elapsed activity time. |
| Core to host | Request an activity by clip ID and anchors, present or dismiss a message, schedule or cancel the next deadline, request a native notification and persist a small record. Each result has plain data and each cancellable operation has an ID so stale completions can be ignored. |

Use widget-local logical pixels for anchors and leave compositor coordinates, DPI scaling, input regions and text shaping to the host. Declare optional capabilities through usable geometry and policy: absent rail geometry makes hanging and swing ineligible, and absent desktop placement falls back to a normal window with its own clock. A harness with a fake clock, geometry and recorded outputs exercises the same behaviour, focus and prayer rules on the current Ubuntu machine. The platform paths below are future design options. The current implementation and test scope is Ubuntu 26.04.1 LTS, GNOME Shell 50.1 on Wayland and AzClock 16.1.

| Host | Porting path |
| --- | --- |
| GNOME on Ubuntu and other distros | Reuse the GJS/AzClock adapter and validate each supported Shell version. Use its clock geometry and Clutter timeline. [GNOME extension compatibility](https://gjs.guide/extensions/overview/updates-and-breakage.html) |
| KDE Plasma and other Linux desktops | Test a Plasma widget first. On other Wayland compositors, use a desktop surface only where the compositor exposes a suitable protocol. Use FreeDesktop notifications where available. [Plasma widget guide](https://develop.kde.org/docs/plasma/widget/) · [Wayland layer-shell protocol](https://github.com/swaywm/wlr-protocols/blob/master/unstable/wlr-layer-shell-unstable-v1.xml) · [FreeDesktop notifications](https://specifications.freedesktop.org/notification/latest/) |
| Windows | Prototype a companion window that owns its clock and avatar, using supported windowing and app notification APIs. Confirm desktop placement and input behaviour in the host prototype. [Windows App SDK windowing](https://learn.microsoft.com/en-us/windows/apps/develop/ui/windowing-overview) · [Windows app notifications](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/) |
| macOS | Prototype a companion window with AppKit and use UserNotifications for optional fallback alerts. Verify placement across Spaces, fullscreen and multiple monitors. [AppKit windows](https://developer.apple.com/documentation/appkit/nswindow) · [Apple UserNotifications](https://developer.apple.com/documentation/usernotifications) |

## Behaviour and timing

The avatar controller owns the current activity, next eligible time, and cancellation. It receives layout and visibility changes, deadlines, menu commands, and clip completion. Tests feed the same interface a fake clock, seeded randomness, and synthetic geometry. The renderer samples a prepared clip against elapsed time and reports completion or cancellation. Frame drawing never chooses a behaviour.

- Start from a still pose. When the visible avatar reaches its next deadline, filter by available space, motion settings, cooldown and asset readiness. Choose from the remaining weighted activities and avoid repeating the last one when another is available. Start with a 60–180 second rest window and tune after profiling. Use one coarse one-shot wakeup for the next ambient decision. [GLib power-efficient timers](https://docs.gtk.org/glib/func.timeout_add_seconds.html)
- Play one sequence at a time, with an entry, optional loop or hold, and exit to the appropriate pose. An explicit menu action supersedes ambient planning. Let visible activity exit at the next safe marker, with one pending command at most. Hide, lock and invalidated layout cancel immediately and release the prop and bubble. Reappearing starts a new rest interval.
- Offer **Start focus session**, **Show a trick**, and **Pause ambient activity** from a keyboard-accessible menu on the avatar. During focus, use a quiet pose and suppress random activity and its bubbles. Prayer reminders follow a separate setting. Keep one completion deadline and use the existing clock update for a visible countdown where available. Default to counting time asleep and reconcile the deadline on resume, completing at most once. A persisted wall-clock deadline is the simplest first implementation and can shift if system time is manually changed. A lock or hidden widget stops visual work while the focus session remains logically active. [systemd sleep and resume signals](https://www.freedesktop.org/software/systemd/man/256/org.freedesktop.login1.html)

## Arabic prayer reminders

Show a quiet, dismissible Arabic bubble next to the avatar for Fajr, Dhuhr, Asr, Maghrib and Isha. Start with two selectable events per prayer, **at prayer time** and **30 minutes before**. Use reviewed Arabic templates with right-to-left layout, locale-aware numbers and accessible text. Keep each variant in the same bubble as other avatar messages. The prayer message takes priority over ambient content and leaves a held pose or running activity undisturbed.

| Event | Arabic bubble |
| --- | --- |
| Fajr starts | حان الآن وقت صلاة الفجر |
| Dhuhr starts | حان الآن وقت صلاة الظهر |
| 30 minutes before Dhuhr | بقيت ٣٠ دقيقة على صلاة الظهر |

- **Schedule source.** Let the user set a city or coordinates, IANA time zone, calculation method, Asr convention and high-latitude rule as needed. Prototype the MIT-licensed Adhan JS core in GJS for offline calculation and compare results against a trusted local timetable for the selected method. Keep prayer schedules as absolute instants derived from the configured location's civil date. Store the location locally. If the configured inputs cannot produce a valid time, skip that reminder and show the issue in settings. [Adhan JS](https://github.com/batoulapps/adhan-js) · [Calculation methods](https://github.com/batoulapps/adhan-js/blob/develop/METHODS.md)
- **Delivery and power.** Keep a rolling schedule for today and tomorrow and arm one one-shot wakeup for the earliest prayer or focus deadline. Recompute at the configured location's midnight, on settings or clock changes and on resume. Deduplicate by configured location, local date, prayer and event kind, including across restarts. Cancel superseded wakeups when settings change. Drop missed advance reminders and only deliver a recently missed start reminder within a short grace period, initially five minutes, using accurate wording for the time elapsed. Keep the next prayer visible on demand. Use no countdown polling, network request or sleep inhibitor.
- **Visibility and focus.** While visible, use the avatar bubble. While covered or locked, optionally route the reminder to the OS notification system with user opt-in and respect system permissions, Do Not Disturb and lock-screen preferences. Otherwise, show a still-fresh reminder on return and skip stale ones. Keep these reminders independent of the ambient pause control, and offer a separate option to mute them during focus. Use one delivery target per event.
- **Existing GNOME setup.** Sajda is already installed and can send its own prayer alerts. Keep the avatar reminder toggle independent, and verify duplicate notification behaviour with Sajda enabled. The portable core can operate from its own local schedule without reaching into another extension's state.

## Clock surfaces and activities

Treat the line beneath the time as the walking surface, its unobstructed end as the seconds-side perch, and the clock card’s right edge as the leaning wall. Use the full track geometry as the support, so a changing progress fill never moves the avatar. Confirm these mappings in the live clock. Use the top line as a separate grab rail, with its height, reach and usable span checked before selecting a hanging activity. AzClock supplies the geometry in clock-local coordinates. Recompute on resize, monitor or scale change, and skip moves whose full body footprint intersects the time, date or screen edge. If the clock is off, use the configured corner as a still fallback.

### Random activity roster

Start with common walking and quiet seated actions, occasional push-ups, and rare rail and swing actions. The scheduler only enables an activity after its clips and contact checks pass. Reuse walking as the approach for a seated or exercise activity when needed. The rest pose fills the gap between activities. Start with salam wave as a menu trick. Focus sessions and prayer reminders are triggered by user input and deadlines, respectively.

| Random activity | Frequency | Sequence and eligibility |
| --- | --- | --- |
| Walk left or right | Common | Turn or start, walk along the clear segment, then stop. Match travel to the authored stride and keep the supporting sole planted on the line. Reauthor the current in-place loop for directional travel. |
| Sit near the clock seconds | Common | Approach the fixed perch, sit, hold, then stand. Require space beyond the time and date, and keep the hips on the seat. Needs a seated clip. |
| Recline against the right wall | Common | Lean or recline, hold, then return to standing. Require space for the full silhouette and keep the back against the wall. Needs a new clip. |
| Count tasbih while seated | Common | Choose a reviewed dhikr or du'a on the first bead-turn marker. Keep it readable across several turns, then allow later markers to change it. Replace the current standing cycle with a seated variant. |
| Read a short surah while seated | Common | Open a book, pick a short surah and display each ayah in order. Give each ayah time to read, advance once per deadline, and end the sequence cleanly on interruption. Needs a book and a reading clip. |
| Do push-ups | Occasional | Lower into position, do a short set, then stand. Require enough horizontal clearance to keep palms and toes planted. Needs new clips. |
| Jump and hang from the top line | Rare | Check take-off, grip and landing before jumping. Reach the fixed rail, hang briefly, then drop and land. Needs new clips. |
| Do a pull-up or pull-over | Rare | Use the same jump and hang entry. Choose a pull-up that returns to the ground or a pull-over that settles on the rail. Require a safe exit for the selected variant and fixed hands during grip. Needs new clips. |
| Ride a swing | Rare | Create the swing only at a valid rail anchor with room for its entire arc. Share a pivot and animation time across the seat, ropes and avatar. Dismount before removing the swing. Needs a swing and new clips. |

Bundle sourced Arabic text locally with surah and ayah IDs. Pick the surah randomly and preserve the text and verse order. Use proper right-to-left rendering and plain text for the bubble. Source and review the dhikr and du'a separately. Tanzil permits distribution of its verbatim Arabic text with attribution, link and copyright notice. Verify rights separately for any translation. [Tanzil text licence](https://tanzil.net/docs/Text_License)

## Smoothness and resource use

The [Ubuntu resource and battery estimate](avatar-resource-estimate.md) measures the current assets and establishes a proposed 0.10 W average pilot target. Validate the target with the first working walk. The 24 MiB budget includes retained pixel buffers and textures, so preparation at 2× may need a smaller display-size asset or a bounded decode window.

1. **Use the compositor clock during motion.** Start one actor-bound Clutter timeline for a visible action. Compute root position and sprite frame from the same elapsed time and change sprite content only when its index changes. Sample the current frame after a delay, with no replay of missed frames. If a delay crosses several text markers, update at most once and retain a readable dwell. Keep transforms fractional. Control the animation with translation and content changes on an existing actor, avoiding layout work on every frame. [Clutter timeline](https://gnome.pages.gitlab.gnome.org/mutter/clutter/class.Timeline.html) · [Clutter actor](https://gnome.pages.gitlab.gnome.org/mutter/clutter/class.Actor.html)
2. **Author contact and transitions in Blender.** Export a stable pivot, contact anchors, stride, and markers with each clip. Preserve the pivot when cropping and scale all coordinates together. Give a looping stride matching start/end phases and remove the duplicated endpoint. Match the exit pose to the next entry pose. Use the current 12 fps clips to prove playback. Try 30 fps for walking, jumps, pull-ups and swing first. Check the cadence at the target refresh rate and judge it on screen before buying more frames. The timeline smooths the actor's translation, while character poses can only change as often as the export provides.
3. **Bound the asset working set.** The six existing sequences contain 264 RGBA frames at 360 × 500. At four bytes per pixel they occupy about 181 MiB decoded, excluding texture overhead. Start with transparent assets cropped and resized offline for the actual display size. Load and decode off the synchronous Shell path and prepare a clip before starting it. Keep the rest sprite and a byte-budgeted active or imminent set, including both pixel buffers and retained textures in measurements. If preparation is slow or fails, keep the current still pose and wait for the next eligible activity. Prototype and profile texture upload on Shell 50 before choosing an atlas; prepacking by itself does not shrink the decoded working set. [GJS event loop and asynchronous I/O](https://gjs.guide/guides/gjs/asynchronous-programming.html)
4. **Stop visual work when it cannot be seen.** Cancel the avatar timeline and ambient wakeup while the desktop is covered, locked, or hidden, using host visibility as the signal and testing coverage separately since a covered actor can still be mapped. Check whether idle and battery modes need ambient motion at all. Honour reduced motion and subscribe to the system power-saver signal where supported. On disable, stop timelines, remove all sources, disconnect signals, cancel outstanding work, invalidate late callbacks, and destroy avatar actors. The extension runs inside GNOME Shell, so keep callback work bounded and avoid synchronous disk or network I/O, child processes during playback, and sleep inhibitors. [GNOME extension review guidelines](https://gjs.guide/extensions/review-guidelines/review-guidelines.html) · [Gio power profile monitor](https://docs.gtk.org/gio/iface.PowerProfileMonitor.html)

## Ubuntu failure scenarios and acceptance checks

### Findings from the current assets and host

- The existing 12 fps walk is front-biased and in place. Moving the sprite sideways as-is risks skating, foot sliding and a hard stop. The rig has foot bones parented to the root, no thigh or knee bones, and a robe weighted to spine and chest. Deep sitting, push-ups and the pull-over need a pose study before committing to extra rig controls or changes to deformation. The beads are bound to the right hand through their own bone. Check that the loop hangs clear of the robe in seated and exercise poses before deciding when it needs to be stowed. [Animation source](../character/3d/anim.py) · [Rig source](../character/3d/rig.py)
- The six existing sequences have transparent margins in every frame. That check says nothing about whether a planted foot stays in place. The wave's first and last exported alpha bounds differ, and the exporter places some return-to-rest keys just beyond the last rendered frame. The walk has matching step-phase keys bracketing the loop. Inspect each actual entry, exit and loop seam on playback. If an action needs a neutral exit, export it once. For a loop, omit the duplicated endpoint. Re-render to a clean scratch output so stale numbered PNGs cannot survive a shorter export. Check that editable actions reopen in the saved Blender file. [Animation source](../character/3d/anim.py)
- AzClock can put widgets in the wallpaper group or above windows, and its local desk-light patch changes input handling for locked widgets. Verify the real clock exposes the assumed line, perch, wall and rail before choosing motion. Test placement and occlusion in both stacking modes and preserve the desk-light knob interaction. [AzClock source](https://gitlab.com/AndrewZaech/azclock)

### Failure matrix

Use seeded inputs for scheduling tests, inspect contact with Blender scratch renders and reproduce Shell failures in a GNOME development session on this Ubuntu machine. Run battery and compositor measurements in the normal session once the basic lifecycle passes. [GNOME Shell debugging guide](https://gjs.guide/extensions/development/debugging.html)

| Simulate on the current Ubuntu machine | Expected behaviour and pass check |
| --- | --- |
| Walk both ways at the smallest and largest supported avatar scales. Inspect a full stride, a turn and a stop. | The supporting sole stays on the line with at most one logical pixel of drift. Travel stops before text or card boundaries. No pop at the loop or stand transition, and prop handedness stays consistent. |
| Scrub seated, reclined, push-up, grab, pull-over and swing extremes before full renders. | No visible robe penetration through hands, legs, support or props at widget size. Hips, palms, toes, grip and swing seat stay at their authored contacts. Only approved sequences enter the random pool. |
| Test a narrow clock, a clock with seconds or lines hidden, a growing progress fill, and a card near a screen edge. | Skip activities whose support or full swept path does not fit. A moving fill leaves the support fixed. Use a grounded still pose, or the configured corner when the clock is off. |
| Drag or resize the clock, change fractional scale, move it between monitors, or unplug a monitor during an activity. | Invalidate old anchors. Cancel safely and remove temporary props and messages. Re-anchor once the new layout settles. Never leave an actor at an obsolete screen position. |

No frame or message backlog, double prop creation or unintended snap to a wrong contact. Keep readable verse dwell and verify memory plateaus within the planned budget. |
| Make every ambient action ineligible, repeatedly draw the same action, or click several commands during a sequence. Toggle reduced motion and power saver mid-action. | Remain still and rearm only a coarse deadline when appropriate. Avoid immediate repetition if alternatives exist. Keep one activity and at most one pending command. Allow focus and enabled prayer reminders in still mode. |

Test with Sajda alerts, denied notifications and a clock change. | Show at most one avatar prayer message per event, respect focus and notification settings, and complete focus once. Skip stale advance reminders. A reading bubble can resume only at its preserved ayah with a fresh dwell while the reading activity remains active. |
| Click around the clock and avatar, tab to the menu and close it with Escape, then repeat with the clock locked. | Only intended avatar and menu regions handle input. The clock remains fixed when locked, the menu stays accessible, and other desktop interactions and desk-light controls still work. |

## Implementation and release checks

The [Ubuntu pilot guide](avatar-pilot.md) covers staging and isolated preview of the first grounded walk.

1. **Prove the host.** In an isolated GNOME session, show a still avatar inside AzClock and support the click menu, corner fallback and repeated enable/disable. Confirm that the overlay can draw above the card and only the avatar or menu accepts input. Treat a locked clock as fixed in place while keeping the avatar menu accessible. Snap a still pose's sole to the measured line. Prove visibility and cleanup while switching windows, workspaces, scale and lock state.
2. **Prove playback and focus.** Use the existing walk, wave and tasbih assets to validate timing, cut points and the focus deadline. Reauthor the in-place walk for travel direction, foot contact and smooth starts and stops. Add deterministic tests for eligible activity selection, cancellation, missing assets, focus completion and missed playback deadlines.
3. **Ship Arabic prayer reminders.** Check notification delivery and deduplication on restart, DST change, location change, resume, focus and hidden desktops. Compare a set of dates with the chosen local timetable, including summer Fajr and Isha at high latitude. Verify Arabic shaping and test denied notification permission.
4. **Add the remaining activity families.** Ship seated tasbih and reading with verified local text, then push-ups, rail moves and swing. Inspect each at normal widget scale. Aim for no more than one logical pixel of planted-foot, grip or seat drift in sampled frames. Verify Arabic rendering and ayah order.
5. **Measure before enabling by default.** Compare the same AzClock setup with the avatar off, visible and still, hidden, and during scripted movement. Hold brightness, refresh rate, scale and workload fixed. Use Sysprof for Shell frame times and CPU, PowerTOP for wakeups, and repeated battery runs for discharge. Report incremental average watts and CPU time with run-to-run variation. Require zero avatar animation callbacks or redraws while hidden, zero avatar network traffic during ambient, focus and prayer operation, stable memory that plateaus across repeated activities, and zero residual sources or actors after disable. Start with a 24 MiB decoded sprite and texture budget for the pilot. As a smoothness gate, aim for at least 99% of expected compositor frame deadlines met during continuous movement on the target machine under light load, and compare with the avatar-off trace. Check high-DPI and fractional scaling, slower hardware, resume, fullscreen and fast layout changes. These are proposed acceptance targets. [Sysprof and compositor timing](https://blogs.gnome.org/chergert/2020/03/14/how-to-use-sysprof-to/) · [GNOME power measurement tools](https://docs.gtk.org/gio/iface.PowerProfileMonitor.html)

### Pilot refinements from desktop pets

- **Use the clock's current geometry.** Publish a complete geometry snapshot when the usable surfaces change. Give each snapshot a revision and bind the activity to that revision. A clip completion or decode result from an older revision cannot restore a pose, prop or bubble. Keep the overlay passive outside a compact hit area around the avatar body and actual menu controls. Check clicks through the transparent PNG margins, including when a prop is drawn. [Shijima-Qt release notes](https://github.com/pixelomer/Shijima-Qt/releases/tag/v0.1.0)
- **Validate and replay clips before profiling.** Check the manifest offline for frame count and timing, anchors and markers, plus entry and exit support. With the test clock, sample one walk at regular and irregular callback cadences, including a missed update. At equal elapsed times the planned position, facing and stride phase should agree. Check that a static seated hold drops the compositor timeline and keeps only a deadline for its next change. [eSheep motion regression checks](https://github.com/Adrianotiger/desktopPet/blob/master/tests/README.md)
- **Keep the focus state and Arabic text readable.** Put the visible countdown and end control in the clock or accessible menu. Start focus immediately from the menu and let the avatar settle into its quiet pose at the safe exit. Keep bubble and timer text sized independently of avatar scale. Use the built-in still pose when a decorative gesture is unavailable, and verify that the focus countdown and Arabic prayer bubble still work with animations disabled. ## Gemini after the offline release

Add an opt-in **Talk** action that opens a separate conversation process on demand. Start with text and one cancellable, time-limited request at a time. Keep a user-supplied key in the system keyring for a personal setup, or use a server-side credential for a shared release. Only send content the user explicitly submits. The companion can show a local listening or speaking animation based on conversation state. Keep Gemini out of the Shell process, focus timer, activity choice and religious text. Conversation failure returns the character to its normal offline behaviour.
