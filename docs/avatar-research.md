# Ubuntu desktop avatar research

## GNOME integration

- The installed extension is Desktop Widgets (Desktop Clock) 16.1, UUID `azclock@azclock.gitlab.com`, on GNOME Shell 50.1. Its listing documents clocks, static text, images and periodic command output. The installed `extension.js` uses GNOME Shell’s desktop background group, `utils.js` stores widget configuration in per-widget GSettings paths, and `elements/image.js` displays one decoded image with an optional refresh interval in whole seconds. Its image settings provide no 12 fps playback control. [Ubuntu renderer decision](adr/0001-reuse-gnome-widgets-on-ubuntu.md) · [GNOME Extensions listing](https://extensions.gnome.org/extension/5156/desktop-clock/) · [Upstream source](https://gitlab.com/AndrewZaech/azclock)
- Add flipbook playback as an element in the existing widget host so the avatar can use the host’s placement and visibility lifecycle. Keep persistent settings in GSettings so the settings app can close while the widgets remain active. The host is GPL-3.0-or-later, which applies to its code if a modified version is distributed. [GNOME GSettings preferences guide](https://gjs.guide/extensions/development/preferences.html#integrating-settings) · [Upstream license](https://gitlab.com/AndrewZaech/azclock/-/blob/main/LICENSE)

## Animation and power

- Use the transparent 360 × 500 PNGs already produced at 12 fps to prove playback. Select the frame from monotonic elapsed time at roughly 83.3 ms per frame. If playback runs late, advance to the frame for the current time. GLib timeouts can run late. Use them for coarse scheduling and use an active-only Clutter timeline for smooth travel, contact and sprite changes on a shared clock. [Blender export script](../character/3d/anim.py) · [GLib timeout](https://docs.gtk.org/glib/func.timeout_add.html) · [GLib monotonic clock](https://docs.gtk.org/glib/func.get_monotonic_time.html) · [Clutter timeline signal](https://gnome.pages.gitlab.gnome.org/mutter/clutter/signal.Timeline.new-frame.html)
- Hold a resting frame between clips and honor GNOME’s `enable-animations` setting. Stop the timer when the avatar is hidden or unmapped, and release its sources and signals on disable. Test the hidden state with an opaque window maximised over the desktop as well as with the avatar toggle off. A covered actor can remain mapped. [GNOME interface schema](https://github.com/GNOME/gsettings-desktop-schemas/blob/master/schemas/org.gnome.desktop.interface.gschema.xml.in) · [Clutter actor mapping](https://gnome.pages.gitlab.gnome.org/mutter/clutter/property.Actor.mapped.html) · [GNOME extension lifecycle](https://gjs.guide/extensions/review-guidelines/review-guidelines.html#remove-main-loop-sources)
- Decode frames asynchronously and reuse a bounded set of ready images during playback. One full-size RGBA frame contains about 0.69 MiB of pixels. The 48-frame idle clip contains about 33 MiB and all 264 checked-in frames contain about 181 MiB of decoded pixels before allocator or texture overhead. Start with assets sized for the actual on-desktop avatar and measure memory and upload cost before expanding the cache. `St.ImageContent.set_bytes()` copies pixels into texture memory. [Blender export script](../character/3d/anim.py) · [GNOME Shell image loading](https://gnome.pages.gitlab.gnome.org/gnome-shell/st/method.TextureCache.load_file_async.html) · [GNOME Shell texture upload](https://gnome.pages.gitlab.gnome.org/gnome-shell/st/method.ImageContent.set_bytes.html)
- On the target laptop, alternate equal-length runs with the avatar disabled, resting, and animating under the same clock settings, display brightness, refresh rate, power profile and background workload. Include a hidden-avatar run to check that its animation stops. Compare GNOME Shell CPU time and sampled work in Sysprof, and compare battery energy loss over long enough runs to exceed sensor granularity. This machine exposes readable `BAT0/energy_now` and `BAT0/power_now`. The Intel RAPL package energy counter was unreadable in this session. Where readable, RAPL measures the reported hardware domain and its counter can wrap at `max_energy_range_uj`. No power difference has been measured yet. [GNOME Sysprof](https://apps.gnome.org/Sysprof/) · [Linux power supply class](https://docs.kernel.org/power/power_supply_class.html) · [Linux powercap](https://docs.kernel.org/power/powercap/powercap.html)

## Deferred Gemini integration

- Keep clip selection and rendering local. A later opt-in Gemini provider can answer text prompts in a conversation process outside GNOME Shell, with a short deadline and a shared provider credential kept on the service side. Conversation state can drive local listening and speaking poses. Google recommends bounded backoff for retryable errors and documents usage and regional restrictions that should be checked before distributing the feature. [Gemini text generation](https://ai.google.dev/gemini-api/docs/text-generation) · [Gemini key security](https://aistudio.google.com/docs/api-key#critical-security-rules) · [Gemini retry strategy](https://aistudio.google.com/docs/troubleshooting#retry-strategy) · [Gemini terms](https://aistudio.google.com/docs/terms#use-restrictions)

## Ayah text

- Use published text keyed by surah and ayah for offline reminders. Tanzil provides verified Unicode Arabic and requires verbatim reproduction, attribution, a link, and retention of its notice. QuranEnc’s Rowwad English translation is a candidate with separate republication terms covering intact content, source attribution and edition version. Verify the exact edition and terms for the chosen bundle and preserve its text and attribution. [Tanzil project](https://tanzil.net/docs/tanzil_project) · [Tanzil text license](https://tanzil.net/docs/text_license) · [Rowwad English edition](https://quranenc.com/en/browse/english_rwwad) · [QuranEnc terms](https://quranenc.com/en/home/about/terms)

## Open-source desktop pet review

| Project | Practice documented by the project | Application to this avatar |
| --- | --- | --- |
| Shijima-Qt and libshijima | The library accepts floor, ceiling and work-area geometry from its host, and its SDL example renders separately. Shijima-Qt fixed floating mascots after workspace changes or window closures on GNOME and added transparent hit-area passthrough where supported. | Keep clock surfaces explicit. Tie each active clip to the host geometry revision so a stale completion cannot put the avatar back on a vanished rail. Test pointer passthrough across the transparent sprite margins. [Library example](https://github.com/pixelomer/libshijima/blob/main/main.cc) · [Shijima-Qt release notes](https://github.com/pixelomer/Shijima-Qt/releases/tag/v0.1.0) |
| eSheep | Animation definitions live in an asset file. Its motion regression checks cover travel at different render cadences, stationary timer shutdown and display changes after disposal. These are tests of its Windows implementation. | Validate the exported animation manifest offline. Replay one walk at different callback cadences and assert the same stride, contact and stopping position at equivalent elapsed times. Measure high-frequency work stopping when the avatar settles. [eSheep repository](https://github.com/Adrianotiger/desktopPet) · [Motion regression checks](https://github.com/Adrianotiger/desktopPet/blob/master/tests/README.md) |
| OpenPets | Pet packs map semantic reactions to available animations with fallbacks. Bubbles, menus and timer indicators are rendered by the host, and the timer indicator scales separately from the pet. Its development harness can advance a fake clock. | Let prayer and focus work even with a missing gesture clip. Place the focus countdown in the existing clock and size Arabic text independently of sprite scale. Exercise both with fake time and missing assets first. [Pet format](https://docs.openpets.dev/pet-format/) · [Pet rendering](https://docs.openpets.dev/pets/) · [Focus controls](https://docs.openpets.dev/official-plugins/) · [Test harness](https://github.com/OpenPetsHQ/openpets#3-test-harness) |

These are source and documentation findings. The Ubuntu plan uses the patterns with AzClock and the existing Blender assets. It keeps the scheduler event-driven and uses native Clutter timing during visible motion. It does not depend on these projects or use their assets. No comparative battery or frame-pacing benchmarks were run.
