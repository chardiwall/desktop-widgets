# Desktop Widget Settings Plan

## First release

Target Ubuntu 26.04 LTS with GNOME. Build a settings app for the Ayah reminder, Clock, and Avatar. Each widget has its own visibility switch, theme, scale or size controls, and display and position settings. Widgets continue running when the settings app closes. Deliver a local-install `.deb`, with guided setup for a clean account and adoption of the three existing widgets on an existing account. Windows gets its own host integration in a later release. Avatar behaviour and communication follow the [avatar architecture](avatar-architecture.md).

The [mockup](../work/desktop-widget-settings-preview.html) uses simulated displays. Immediate visibility switches and **Apply** and **Cancel** for appearance and placement are the interaction baseline. The next design pass can add miniature theme previews and drag-to-place alongside the nine-position grid. Keep desktop profiles and the wardrobe wave preview as follow-ups once their dependencies pass the checks below.

## Ubuntu pilot

The native GTK 4 and libadwaita pilot controls visibility for the three configured widgets. Ayah and Clock each have five theme previews and Custom, with fill transparency, searchable system fonts, colour, width, and placement controls. Appearance previews stay in the settings app until Apply.

Build with `./packaging/build-deb.sh` and install from the repository root with `sudo apt install ./dist/desktop-widget-settings_0.3.0_all.deb`. Run `desktop-widget-settings --install-gnome-integration` as your desktop user, then sign out and back in. The integration backs up the local AzClock 16.1 `extension.js` as `extension.js.before-desktop-widget-settings` and disables the old `desk-light.service` watcher. AzClock then keeps the cord aligned with Ayah and the avatar in front of Clock, using their rendered positions. The existing avatar player continues to supply animation frames. To revert, restore the backup over `extension.js`, re-enable `desk-light.service` if previously enabled, and sign out and back in.

The Lantern Dial launcher and GNOME status icon share the same shape. Left-click opens the settings and visibility shortcuts. Right-click opens the shorter menu with **Quit Desktop Widgets**. Quit stops the managed widgets and the legacy avatar player for the current GNOME Shell session, closes settings, and hides the indicator. Relaunching restores the saved switches and resumes a previously running legacy player. A new GNOME Shell session starts with the saved widget switches.

Launch **Desktop Widgets** from the application menu. Run the settings tests with `/usr/bin/python3 -m unittest discover -s tests -v` and the session visibility checks with `gjs -m tests/widget-attachments.js`. Clean-account setup, separate Arabic typography, live desktop previews, and persistent monitor reconnect handling remain release work.

## Findings from the current Ubuntu setup

- The installed AzClock extension stores a numeric monitor index and fractional coordinates. It falls back to the primary display when the index is absent. If that index is reassigned to a different display, it can resolve to the wrong monitor.
- The legacy `desk-avatar.service` writes avatar position independently. Its player uses monitor index zero, fixed clock padding and width, and assumptions about which line contains the progress track. It sets image size at startup and recomputes placement on size changes. The legacy placement self-test passes for its fixed geometry fixture. The incoming avatar host design calls for measured clock-local geometry.
- The installed ayah and clock scripts have built-in font and layout choices and read one shared pull-cord colour. Independent card themes need settings to reach the real renderers. Real display identity, renderer changes, and service migration still need an isolated GNOME test.

## Failure scenarios and acceptance checks

| Priority | Failure scenario | Planned behaviour and acceptance check |
| --- | --- | --- |
| Release gate | Unplugging, reordering, or reconnecting displays moves a widget to the wrong screen. | Keep the saved display preference separate from the temporary display used at runtime. Verify which identifiers GNOME exposes across reconnect, dock changes, login, and identical monitors. Temporarily use the primary display when the preferred display is absent and restore the preferred placement when its identity is confirmed. Test index reuse and ambiguous matches. |
| Release gate | A resized widget falls under a panel, clips off a portrait display, or jumps when dragged across a fractional-scale boundary. | Resolve anchors and offsets in display-local logical coordinates and use the usable work area. Clamp the visible bounds after a display or size change. Test the nine anchors on portrait, ultrawide, and mixed-scale displays, including a display to the left of the primary. Use the same placement rules for keyboard nudges and dragging. |
| Release gate | The avatar floats, covers the time, or keeps snapping back after the settings app moves it. | Give the host one owner for placement. Verify handoff from the legacy service. When the avatar and visible clock are assigned to the same display and the track has a safe perch, use its measured geometry. Use the saved avatar position otherwise. Test small cards, large fonts, scale changes, toggling the clock, missing geometry, and repeated enable or disable. |
| Release gate | Applying a theme makes the Ayah hard to read, drops Quranic marks, or replaces a custom theme. | Keep preset values and custom values independently recoverable. Check real Pango rendering with long Arabic and English samples, missing fonts, large text, and both bright and busy wallpaper. Provide a known-good Arabic font fallback and an opaque card option. Verify changing the clock theme leaves the ayah untouched. |
| Release gate | Preview edits survive a crash, overwrite another settings change, or undo an immediate visibility toggle. | Separate draft appearance and placement from saved visibility. Define how the host restores the last committed appearance after a failed apply or interrupted preview. Test Cancel, close, crash, relaunch, concurrent settings changes, and a display disconnect mid-preview. Preserve unapplied edits on a recoverable error and report the failing operation. |
| Release gate | Install or upgrade duplicates widgets, changes third-party widgets, or leaves two avatar players running. | Exercise fresh install, adoption, repeat setup, extension unavailable or disabled, upgrade, and rollback in test accounts. Preserve unrelated widgets, back up the three relevant settings before migration, and verify that one avatar runtime owns playback after adoption. Use the user's session for per-user configuration. |
| Mockup and pilot | Drag snapping grabs the wrong target, becomes fiddly at display edges, or blocks normal desktop clicks. | Add drag in the placement preview first. Provide the position grid and keyboard nudges for the same result. Test a drag between displays, cancellation, overlapping widgets, and snapping at corners. Verify the real widgets keep their normal input behaviour after Apply. |
| Follow-up | A desktop profile partly applies or restores stale monitor assignments. | Before enabling profiles, specify that loading a profile stages the three widgets' themes, placements, and visibility as one operation. Test missing displays, unsupported profile versions, Cancel, and a simulated write failure. Keep profiles out of the release gate until restore and rollback are proven. |
| Follow-up | The wardrobe wave keeps playing after the user closes the preview, or ignores Reduced Motion. | Make a wave a one-shot preview using an existing clip. Show a still pose for Reduced Motion and missing assets. Verify playback stops on close, hide, and widget disable. Reuse the [avatar performance checks](avatar-architecture.md#implementation-and-release-checks). |

## Practices from Cinnamon Desklets

Cinnamon ships a built-in clock desklet on Ubuntu. Its settings and runtime provide a reference for placement, discovery, and widget lifecycle. These are candidates to validate on GNOME. [Ubuntu package file list](https://packages.ubuntu.com/resolute-updates/all/cinnamon-common/filelist)

- **Lock placement and show the snap destination.** Cinnamon offers a position lock and draws a placeholder at the snapped position. It also re-snaps existing positions when its global snap setting changes. For this app, lock desktop positions outside explicit editing and apply snap settings to the widget being moved. Verify the drop matches the placeholder, Cancel clears it, and a snap preference change leaves existing positions intact. [Cinnamon desklet settings](https://github.com/linuxmint/cinnamon/blob/master/files/usr/share/cinnamon/cinnamon-settings/modules/cs_desklets.py) · [Cinnamon drag and snap source](https://github.com/linuxmint/cinnamon/blob/master/js/ui/deskletManager.js)
- **Show where an enabled widget landed.** Cinnamon briefly marks a newly added desklet and offers a widget-specific Configure action. Prototype a **Locate on desktop** action from the settings app. Follow the effective monitor after fallback and honour Reduced Motion with a static cue. Verify the action finds the correct widget on a second display and preserves desktop input. [Cinnamon desklet actions](https://github.com/linuxmint/cinnamon/blob/master/js/ui/desklet.js)
- **Keep setup usable when downloads fail.** Ubuntu Cinnamon reported and fixed a failure in its remote desklet download path. Bundle the initial presets with the app. Show separate states for a missing host, a disabled host, and a widget switched off, with an action appropriate to each. Test offline launch with the host present and with the host missing. Verify that local edits remain available and a failed download can be retried. [Ubuntu Cinnamon release notes](https://ubuntucinnamon.org/ubuntu-cinnamon-26-04-1-resolute-raccoon-released/)
- **Tie updates to the widget lifecycle.** Cinnamon’s clock listens for wall-clock updates when added and disconnects when removed. Validate the equivalent behaviour for this clock and reuse the avatar’s existing lifecycle checks. Verify one active update path after repeated toggles, current time on resume, and no widget-specific polling while that widget is off. [Cinnamon clock source](https://github.com/linuxmint/cinnamon/blob/master/files/usr/share/cinnamon/desklets/clock%40cinnamon.org/desklet.js)

## Implementation order

1. Update the UI mockup for miniature theme previews and the placement interaction. Review theme selection, keyboard positioning, and the monitor-disconnected state before handing it to implementation.
2. Use Context7 and current upstream documentation to compare settings UI, GNOME integration, and Debian packaging options. Prove display identity, geometry, persistence, and extension compatibility in an isolated GNOME session before choosing an integration strategy.
3. Use the architecture skills to define settings ownership, draft and commit semantics, and the contract with the avatar host. Keep platform-specific display and rendering concerns behind that contract.
4. Use test-first development and Ponytail for the smallest complete Ubuntu slice. Start with disabled or missing hosts, independent toggles, saved settings, display fallback, and avatar attachment. Add theme and package integration checks before shipping.
5. Test the `.deb` in a clean Ubuntu account and a copy of the existing setup. Verify that settings survive a new login and that the previous configuration can be restored after an interrupted upgrade.
